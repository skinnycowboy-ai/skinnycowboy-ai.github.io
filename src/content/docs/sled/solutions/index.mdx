## Virtualization modernization

**Challenge.** Platform lifecycle, capacity, cost, datacenter change, or skills
pressure can create a need to move virtual machines. That does not mean every
application must be rewritten at the same time.

**Platform approach.** Evaluate Red Hat OpenShift Virtualization and Migration
Toolkit for Virtualization alongside the required OpenShift storage, networking,
backup, identity, and operations design.

**What to validate.** Workload dependencies, supported guest operating systems,
network and storage mappings, migration windows, backup and recovery, target
capacity, acceptance tests, operational ownership, and rollback conditions.

## Application platform standardization

**Challenge.** Application teams may use different delivery paths, runtime
controls, promotion methods, and policy checks. Releases slow down when ownership
and evidence disappear between handoffs.

**Platform approach.** Evaluate Red Hat OpenShift as a shared application
platform, with Red Hat OpenShift GitOps and the source, build, registry, policy,
and observability systems the organization already uses.

**What to validate.** Application ownership, declarative configuration, build
and promotion boundaries, policy enforcement, secrets, observability, rollback,
and the division of responsibility between platform and application teams.

## Disconnected and controlled operations

**Challenge.** Restricted networks, sovereignty requirements, or security
boundaries control how software enters an environment. The lasting problem is
the complete content lifecycle—not only the first installation.

**Platform approach.** Evaluate OpenShift disconnected installation and update
workflows, registry architecture, the oc-mirror plugin, and repeatable automation
for controlled transfer and evidence capture.

**What to validate.** Approved upstream sources, staging, scanning, integrity,
provenance, capacity, transfer cadence, missing dependencies, exception handling,
promotion, rollback, and retained evidence.

## Private and governed AI

**Challenge.** Public-sector AI use cases may involve sensitive data, controlled
model access, restricted networks, limited accelerator capacity, and a need to
explain how a result was produced.

**Platform approach.** Evaluate Red Hat OpenShift AI on Red Hat OpenShift for
model serving, data access, evaluation, resource governance, monitoring, and
operational control.

**What to validate.** Data handling, model provenance, access policy, retrieval
boundaries, evaluation criteria, quotas and accelerators, monitoring, update and
rollback paths, and ownership after the initial evaluation.

## Human-governed remediation

**Challenge.** Security teams can identify vulnerabilities faster than
application and operations teams can safely correct them. A production change
still requires context, testing, approval, deployment control, verification, and
rollback.

**Platform approach.** Project Lightwell maps a human-controlled remediation
workflow to capabilities that may include Red Hat Advanced Cluster Security for
Kubernetes, Red Hat OpenShift AI, Red Hat OpenShift, Red Hat Ansible Automation
Platform, and Git-based delivery workflows.

**What to validate.** Finding context, prioritization criteria, model and prompt
provenance, compatibility and regression tests, separation of duties, human
approval, production credentials, deployment, verification, rollback, and the
evidence retained at every gate.

:::caution[Project Lightwell boundary]
Project Lightwell is a **field-developed buying motion** and demonstration
concept. It is **not a Red Hat product** or a fixed reference architecture.
Product mappings and workflow designs must be validated against the current
customer architecture, product documentation, subscriptions, and support
boundaries.
:::

## See the ideas tested

[Project Vaquero](/project-vaquero/) is a compact demonstration lab used to test
bounded workflows, integrations, failure conditions, and evidence collection.
A successful lab run shows what happened on the recorded lab architecture under
the recorded conditions. It does not establish production sizing, availability,
resilience, security approval, compliance, supportability, or disaster recovery.
